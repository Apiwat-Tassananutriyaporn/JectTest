============================================================
1. ภาพรวมเป้าหมายของโครงการ
============================================================

โครงการนี้คือ Web-based 3D SCADA / HMI Platform สำหรับสร้างหน้าจอ
Monitoring และ Control แบบ 3D โดยผู้ใช้สามารถสร้าง project, วาง model,
วาง component, ตั้งค่า tag, เชื่อมต่อ protocol, ตั้ง alarm, ทำ dashboard,
จัดการสิทธิ์ผู้ใช้, บันทึกข้อมูลผ่าน backend/database และเตรียมระบบสำหรับ
gateway / PLC integration ได้

งานหลักที่ต้องเสร็จในโครงการนี้:

- Frontend SCADA editor
- 3D Scene Editor
- Component 2D และ Component 3D พื้นฐาน
- 3D Component Design System ให้เป็น theme เดียวกัน
- Project / Scene / Model / Component management
- Tag configuration
- MQTT Direct Topic
- Backend API
- Database persistence
- Gateway configuration
- PLC/Gateway integration ผ่าน simulator/mock gateway ก่อน
- Alarm configuration และ Alarm Log
- Dashboard gauge/chart
- User permission: watchable, controlable, editable
- Auth/Permission structure สำหรับต่อยอด production
- Integration test
- Deployment environment
- งานเล่มปริญญานิพนธ์
- Documentation, Demo, Presentation

แนวคิดสำคัญของแผน:

- กรกฎาคมเน้น frontend editor ให้ใช้งานได้จริงก่อน
- สิงหาคมปิด frontend prototype ให้ค่อนข้างนิ่ง
- กันยายนเน้น backend + database + API + save/load ให้เสถียร
- ตุลาคมใช้ MQTT Gateway หรือ PLC Simulator เป็นหลักเพื่อลดความเสี่ยง
- งานเล่มไม่เริ่มหลังระบบเสร็จทั้งหมด แต่เริ่มขึ้นโครงช่วงปลาย dev
- deployment ไม่ควรไว้ท้ายสุด ต้องทดลองก่อนเข้าสู่ช่วง demo
- พฤศจิกายนเน้น final integration, deployment, งานเล่ม, bug fix, presentation

5. Risk และแนวทางลดความเสี่ยง
============================================================

Risk 1: PLC/Gateway pattern เปลี่ยนกลางทาง
แนวทาง:
- ทำ PLC/Gateway เป็น protocol adapter
- ให้ทุกอย่างอ่านผ่าน canonical tag values
- ใช้ PLC Simulator/mock gateway เป็น demo path หลักจนกว่า PLC จริงพร้อม

Risk 2: Backend เริ่มเร็วเกินไปทั้งที่ frontend direction ยังไม่นิ่ง
แนวทาง:
- ใช้มิถุนายนเพื่อทดลอง frontend demo
- ใช้กรกฎาคม-สิงหาคมทำ frontend prototype ให้ค่อนข้างนิ่ง
- Lock frontend direction ก่อนเริ่ม backend หนัก

Risk 3: งาน 3D component ใช้เวลานานเกิน
แนวทาง:
- ทำเฉพาะ component 3D พื้นฐานก่อน
- จำกัดเวลาออกแบบไม่เกิน 1 สัปดาห์
- ใช้ theme/material rule เดียวกันเพื่อลดเวลาตัดสินใจ

Risk 4: กันยายน scope แน่นเกินไป
แนวทาง:
- กันยายนโฟกัส backend/database/API/save-load ให้เสถียร
- เลื่อน MQTT Gateway และ PLC Simulator ไปตุลาคม
- ไม่เริ่ม PLC จริงในกันยายน

Risk 5: ตุลาคม gateway/PLC ไม่เสถียร
แนวทาง:
- ทำ MQTT Gateway ก่อน
- ทำ PLC Simulator/mock gateway เป็นหลัก
- PLC จริงเป็น optional integration ถ้าอุปกรณ์และสเปกพร้อม

Risk 6: งานเล่มไปกองช่วงท้ายเกินไป
แนวทาง:
- เริ่มขึ้นโครงเล่มในกันยายน
- เริ่มเขียนส่วนต้นในตุลาคม
- เขียนผลการพัฒนาและการทดสอบในต้นพฤศจิกายน
- ใช้ครึ่งหลังพฤศจิกายนสำหรับ revision ไม่ใช่เริ่มเขียนจากศูนย์

Risk 7: Deployment เจอปัญหาช่วงใกล้ demo
แนวทาง:
- ทดลอง deployment ตั้งแต่ตุลาคม
- มี deployment trial ก่อน final demo
- Lock demo environment ภายในสัปดาห์ที่ 2 ของพฤศจิกายน

Risk 8: งานไปกองปลายเดือนพฤศจิกายน
แนวทาง:
- ตั้ง feature complete ที่ 2026-11-15
- ไม่เพิ่ม scope ใหญ่ใหม่ในพฤศจิกายน
- เก็บ 2026-11-16 ถึง 2026-11-30 เป็น buffer จริง

============================================================
6. Definition of Done ระดับโครงการ
============================================================

เมื่อถึง 2026-11-15 ระบบควรมีสิ่งต่อไปนี้:

- สร้าง/เปิด/แก้ project ได้
- สร้างและแก้ scene ได้
- วาง component/model ใน scene ได้
- มี component 3D พื้นฐานที่เข้ากับ theme เดียวกัน
- ผูก tag กับ component/model ได้
- MQTT Direct Topic ใช้งานได้
- Backend API ใช้งานได้
- Database เก็บ project/config/runtime ที่จำเป็นได้
- Project save/load ผ่าน backend/database ได้
- Gateway config ใช้งานได้
- MQTT Gateway หรือ PLC Simulator ส่งข้อมูลเข้า tag กลางได้
- PLC จริงเชื่อมได้ถ้าอุปกรณ์และสเปกพร้อม แต่ไม่ใช่ blocker ของ demo หลัก
- Text Output, Switch, Gauge, Dashboard, Alarm ทำงานจาก tag values ได้
- Model action ทำงานจาก tag values ได้
- User permission ใน project มีพื้นฐาน:
  - watchable ดูได้ แต่ control/edit ไม่ได้
  - controlable ดูและ control ได้ แต่ edit config/layout ไม่ได้
  - editable ดู, control, และ edit config/layout ได้
- Full integration test ผ่านใน flow หลัก
- Demo scenario เล่นได้ครบ
- Demo environment deploy ได้จริง
- งานเล่มมีเนื้อหาครบตามที่ต้องส่ง
